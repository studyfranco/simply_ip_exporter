## `src/` — entry points

| File | Responsibility |
| :--- | :--- |
| `src/main.rs` | Process entry point. Loads `.env`, initializes `tracing`, reads `RuntimeConfig`/`INITIAL_MASTER_KEY`, connects the DB, runs migrations, builds the `SecretCipher`, runs `bootstrap_master_key` (mints and once-prints the Master key/signing secret if `api_keys` is empty; supports deterministic `INITIAL_MASTER_KEY`/`INITIAL_MASTER_SIGNING_SECRET` for CI), then `verify_encryption_key` (a canary decrypt of the Master key's sealed `signing_secret` — `SecretCipher::from_env` only checks the configured key is 64 hex characters, so a syntactically valid but *wrong* key would otherwise pass silently and only surface later as opaque per-request `401`s; this aborts boot loudly instead, `exit(1)` with an explicit log line), pins the Master identity via `MasterPin::pin_at_boot`, spawns the sync worker, binds the listener, and serves with graceful shutdown (`SIGINT`/`SIGTERM`). Has its own `#[cfg(test)]` module covering `verify_encryption_key`. |
| `src/lib.rs` | Library root (`#![warn(missing_docs)]`). Declares every module, the `MAX_REQUEST_BODY_BYTES` constant shared between the router's `DefaultBodyLimit` and `middleware::MAX_SIGNED_BODY_BYTES`, and `create_app(AppState) -> Router` — the single place the full route table is assembled (probes and `/feed/v1/*` outside `auth_middleware`; `/api/*` nested behind it; `static/` as the fallback service). |

## `src/` — shared foundations

| File | Responsibility |
| :--- | :--- |
| `src/state.rs` | `AppState`: the `Clone`-cheap bundle of `db`, `config`, `cipher`, `replay_guard`, `master_pin`, `ip_cache`, `rate_limiter`, and an optional `vault_client`, threaded through every handler via Axum's `State` extractor. |
| `src/config.rs` | `RuntimeConfig::from_env()` and everything it depends on: `TrustedProxies`/`resolve_client_ip` (the `X-Forwarded-For`/`X-Real-IP` trust-boundary logic — headers are honored only from a configured trusted peer), `resolve_bind_addr`/`parse_bind_addr` (`BIND_HOST`/`PORT`), and `validate_initial_master_key` (the strict-hex, fail-closed check on `INITIAL_MASTER_KEY`). `TrustedProxies` (rewritten 2026-08-19, ported from `example/simply_ip_vault`/`example/simply_hook_executor`'s identical design — see `AGENT_NOTES.MD`): `ProxyMatcher::{Network, Hostname}` — a hostname/Docker container name (e.g. `traefik_tomidejetsu`) is accepted at parse time whether or not it currently resolves (only a genuinely malformed entry is fatal), then resolved via `tokio::net::lookup_host` with a positive/negative TTL cache (`resolved()`, awaited per request in `middleware.rs`/`feed.rs`) and a boot-time `prime_with_grace()` (resolves once immediately, retries once after a 60s grace period on a detached task, never blocks or fails startup on a DNS outage). |
| `src/error.rs` | `AppError`, the single enum every handler returns via `Result<_, AppError>`, and its `IntoResponse` impl — the one place HTTP status codes and the `{"error": "..."}` envelope are decided. Includes `BodyRejected(StatusCode, String)`, which lets `src/extract.rs`'s strict extractors normalize a rejected request into this envelope while still passing through a non-`400` status (e.g. `413`) verbatim, and `ConflictWithDetails { message, details }` (2026-08-19, matching `example/simply_ip_vault`'s identical variant) — a `409` whose body merges structured machine-readable detail (e.g. the endpoints blocking a key delete) alongside `error` at the top level, matched ahead of the flat status/message table since it's the one variant whose body isn't just `{"error": ...}`. |
| `src/extract.rs` | `StrictJson<T>`/`StrictPath`/`StrictQuery<T>` (the last added 2026-08-19): wrappers around axum's built-in `Json`/`Path`/`Query` extractors that remap a rejection (malformed body, invalid UUID segment, malformed or unrecognized query parameter) through `AppError` instead of axum's own plain-text rejection body — closing a gap where a malformed request bypassed this service's error envelope entirely. `StrictQuery` only normalizes rejection *shape*; a query struct still needs its own `#[serde(deny_unknown_fields)]` to make an unrecognized parameter a rejection at all (see `api::audit::AuditLogQuery`). Used by every mutating handler in `api/keys.rs` and `api/endpoints.rs`, and by `api/audit.rs`'s query-string parsing. Has its own `#[cfg(test)] mod tests` exercising `StrictQuery` directly against hand-built `Parts` (no router needed). |
| `src/crypto.rs` | Two independent primitives sharing a file because they protect the same column (`api_keys.signing_secret`): `canonical_v1_payload`/`compute_signature`/`verify_signature` (the `CANONICAL_V1` HMAC-SHA256 scheme used both inbound and outbound), and `SecretCipher` (XChaCha20-Poly1305 sealing, keyed by `EXPORTER_ENCRYPTION_KEY`, with a plaintext fallback when unset). |
| `src/master.rs` | `MasterPin`: resolves and freezes the Master key's UUID once per process (`pin_at_boot` at startup; `resolve`/`authenticate` for on-demand use), so a direct-database `UPDATE api_keys SET is_master = true` on a different row cannot elevate that row without a restart. `pin_at_boot` checks the `master_marker` unique index via `crate::db::has_index` (not `sea_orm_migration::SchemaManager::has_index` — see `db.rs`'s entry for why). |
| `src/replay.rs` | `ReplayGuard`: an in-memory, self-pruning `HashMap` of recently-accepted `(key_id, digest)` pairs, enforcing single-use signatures within the `SIGNATURE_MAX_AGE_SECONDS` window. Bounded at 250k entries with backoff-limited sweeps under sustained saturation. |
| `src/db.rs` | `connect`/`run_migrations`/`apply_sqlite_pragmas`: builds the SQLite pool pinned to exactly one connection (`SQLITE_MAX_CONNECTIONS = 1`), declares `journal_mode=WAL`/`synchronous=NORMAL`/`foreign_keys=ON`/`busy_timeout` at connect time, and confirms them afterward. Also `has_index` (2026-08-18, ported from `example/simply_ip_vault`): a per-backend catalog query (`sqlite_master`/`pg_indexes`/`information_schema.statistics`) used by `master.rs::pin_at_boot` instead of `sea_orm_migration::SchemaManager::has_index`, which answers `BackendNotSupported` on PostgreSQL rather than correctly reporting the index. |
| `src/middleware.rs` | `auth_middleware`: the Axum middleware guarding every `/api/*` route. Resolves `state.config.trusted_proxies.resolved().await` first (a refcount bump when no `TRUSTED_PROXIES` hostname is configured; a possible DNS lookup, cached, otherwise), validates `X-Timestamp` before touching the database, looks up the key by `X-API-Key`, applies `MasterPin::authenticate`, verifies the mandatory `X-Signature-256` over the full request target, checks `ReplayGuard`, and only then evaluates `bound_ips` — cheapest-and-unauthenticated checks first, network authorization last. A `Content-Length` over the router's body limit is rejected as `413` before any of the body is read; the same limit hit mid-stream (a `Content-Length`-less chunked body) falls back to the same `413` via `to_bytes`'s own cap. |

## `src/` — in-memory cache, IP pipeline, and Vault sync

| File | Responsibility |
| :--- | :--- |
| `src/cache.rs` | `IpCache`: the `Arc<RwLock<HashMap<Uuid, EndpointCache>>>` at the center of the "zero disk wear" requirement. `apply_full`/`apply_diff` merge Vault's full/differential sync responses; `snapshot` returns an endpoint's current live networks; `full_sync_due` tracks the 24h full-resync clock in-process (via `tokio::time::Instant`, not persisted — a restart re-triggers an immediate full sync, which is correct). `parse_target_address` accepts both bare addresses and CIDR notation. |
| `src/ipfilter.rs` | `filter_and_aggregate`: the output sanitization pipeline. Static `RFC1918`/`LOOPBACK`/`BOGONS` range tables (lazily built via `std::sync::LazyLock`), an `overlaps_any` containment check applied per configured flag, and a final `ipnet::IpNet::aggregate()` pass to collapse the survivors into the smallest equivalent CIDR set. |
| `src/vault_client.rs` | `VaultClient`: the outbound, `CANONICAL_V1`-signed HTTP client for `GET /api/ips`. `fetch_ips(groups, since)` builds either a full query (no `since`) or a differential one (`since=<ts>&include_deleted=true`), signs it, and deserializes Vault's `VaultApiRecord` shape (`target_address`, `updated_at` as `chrono::NaiveDateTime`, `is_deleted`). `from_config` returns `None` when `VAULT_BASE_URL`/`VAULT_API_KEY`/`VAULT_SIGNING_SECRET` aren't all set. |
| `src/sync.rs` | `spawn_sync_worker`: the background `tokio::spawn` loop (15s tick) implementing the hybrid protocol described in `README.md` — per endpoint, a full sync when 24h have elapsed (or none has ever run) and a differential sync when `ttl_seconds` has elapsed since `endpoints.last_synced_at`, updating that DB column after each successful sync and logging-and-continuing (never failing the process) when Vault is unreachable. |
| `src/ratelimit.rs` | `RateLimiter`: the public feed's anti-DoS gate. A `Mutex`-protected `HashMap<IpAddr, Instant>` plus an insertion-ordered eviction queue, capped at `MAX_TRACKED_IPS = 10,000`, enforcing `RATE_LIMIT_WINDOW = 120s` per source IP. |
| `src/feed.rs` | `serve_feed`, the `GET /feed/v1/{token_secret}/list.txt` handler. Resolves the client IP, looks up the endpoint by token (`404` if unknown), checks `bound_ips` (`403` if disallowed), aggregates+filters the cached snapshot, computes the SHA-256 `ETag`, answers a matching `If-None-Match` with a free `304` (no rate-limit consumption — see the ordering rationale in the file's own doc comment), and otherwise applies the rate limiter before returning the full `text/plain` body. |

## `src/api/` — admin API (`/api/*`, behind `auth_middleware`) and probes

| File | Responsibility |
| :--- | :--- |
| `src/api/mod.rs` | Module declarations and `pub use` re-exports consumed by `lib.rs`'s route table. |
| `src/api/support.rs` | Shared helpers: `generate_random_key`/`hash_key` (credential minting/lookup), `validate_bound_ips` (parses and validates a comma-separated CIDR/address list), `describe_resource` (renders a `kind:id (name)` audit-log target reference), and `create_audit_log` (writes one `audit_logs` row; propagates a write failure rather than swallowing it, since the mutation it follows has already committed — see its doc comment). `create_audit_log` is generic over `sea_orm::ConnectionTrait` (2026-08-19, not a concrete `&DatabaseConnection`) so a caller running a multi-step mutation inside `db.transaction(...)`/`db.begin()` (e.g. `api::keys::delete_api_key`'s endpoint reassignment) can pass the transaction handle directly, committing or rolling back the audit entry atomically with the mutation it describes. |
| `src/api/guards.rs` | Authorization decisions shared by more than one `api/keys.rs` handler, centralized 2026-08-19 (previously inlined per handler): `require_master`, `guard_master_delete_or_rotate` (refuses deleting/rotating the Master key), `guard_master_update` (refuses a `PUT /api/keys/{id}` touching the Master's `name`/`can_manage_keys` — `bound_ips` is the one field still changeable). Deliberately small: this crate's two-tier RBAC has no delegated-grant conjunction rules to centralize the way `example/` peers' larger `api/guards.rs` files do — see `AGENT.MD`'s "Why two tiers, not three". |
| `src/api/auth.rs` | `GET /api/auth/me` — reports the caller's own identity and RBAC flags, so the SPA (and this README's curl example) can authenticate once and introspect what it's allowed to do. |
| `src/api/keys.rs` | CRUD for `api_keys`, every route gated `require_master` (`api::guards`): `create_api_key` (mints a Daughter key, returns its plaintext secret + signing secret exactly once), `list_api_keys`, `update_api_key` (name/`bound_ips`/`can_manage_keys` — `is_master` is not a field on the payload type, so it cannot be set through the API by construction; `guard_master_update` additionally refuses a `name`/`can_manage_keys` change when the target is the Master, 2026-08-19), `rotate_api_key` (`guard_master_delete_or_rotate` refuses the Master). `delete_api_key` (2026-08-19, substantially rewritten): judges concurrent-delete success on `rows_affected`, not merely "the query didn't error"; if the target key owns any `endpoints` and the request carries no `?reassign_to=<key id>` (`StrictQuery<DeleteKeyQuery>`), refuses with `409` and a structured `AppError::ConflictWithDetails` inventory (`owned_endpoints: [{id, name}, ...]`) instead of silently orphaning them via the schema's `ON DELETE SET NULL`; with `reassign_to`, the reassignment (`Endpoint::update_many().col_expr(...)`, portable across SQLite/PostgreSQL/MariaDB) and the delete run inside one `state.db.begin()`/`txn.commit()` transaction, including the audit write. `CreateKeyPayload`/`UpdateKeyPayload`/`DeleteKeyQuery` all carry `#[serde(deny_unknown_fields)]` — a stray field is refused with a `400` naming it, not silently dropped. Every mutating route writes a `KEY_CREATE`/`KEY_UPDATE`/`KEY_DELETE`/`KEY_ROTATE` audit entry after its write commits. |
| `src/api/endpoints.rs` | CRUD for `endpoints`. `create_endpoint` — any authenticated key may call it; the new row is owned by the caller. `list_endpoints` — Master sees every row, a Daughter sees only its own (`owner_key_id` filter). `update_endpoint`/`delete_endpoint` — gated by `may_manage` (Master or owner); `delete_endpoint` has the same `rows_affected`-checked concurrent-delete handling as `delete_api_key`. `reassign_endpoint_owner` — Master only. `CreateEndpointPayload`/`UpdateEndpointPayload`/`ReassignOwnerPayload` all carry `#[serde(deny_unknown_fields)]` (2026-08-18, same rationale as `keys.rs`). Every mutating route writes an `ENDPOINT_CREATE`/`ENDPOINT_UPDATE`/`ENDPOINT_DELETE`/`ENDPOINT_OWNER_REASSIGN` audit entry after its write commits. |
| `src/api/audit.rs` | `GET /api/audit-logs` — lists the audit trail, most recent first, optionally filtered by exact `action` and paginated (`limit`, capped at 500; `offset`), via `StrictQuery<AuditLogQuery>` (2026-08-19; `AuditLogQuery` carries `#[serde(deny_unknown_fields)]`). Master-only: audit entries span every key and endpoint in the system, so a scoped Daughter key seeing them would be an RBAC leak regardless of what it owns. |
| `src/api/health.rs` | `health_check` (`GET /health`/`/healthz`, always `200`, no DB query) and `readiness_check` (`GET /ready`/`/readyz`, `200` only when an `api_keys` count query succeeds — an ordinary SeaORM query, not raw SQL — and `MasterPin::get()` is `Some`). Both mounted outside `auth_middleware` in `lib.rs`. |

## `tests/` — automated test suites

| File | Responsibility |
| :--- | :--- |
| `tests/integration.rs` | End-to-end-in-process tests driving the real Axum router (via `tower::ServiceExt::oneshot`) against an in-memory SQLite database: health/readiness probes — including readiness failing independently on a genuinely broken database (an unmigrated connection) with the Master already pinned, not just on an unpinned Master — unsigned/signed/replayed/stale-timestamp admin API requests, Master-vs-Daughter RBAC on both `api_keys` and `endpoints`, the full feed pipeline (aggregation, RFC1918 filtering, ETag/304 including the "conditional revalidation bypasses the throttle" property, 429 rate limiting, `bound_ips` enforcement, unknown-token `404`), audit logging (every key/endpoint mutation writes the expected entry with correct attribution, `GET /api/audit-logs` is Master-only, and its `action` filter narrows results), malformed-request handling (`StrictJson`/`StrictPath`/`StrictQuery`'s `{"error": ...}` envelope, `413` vs `400`, and an unknown field in a mutating payload or query string naming itself in a `400` rather than being silently dropped), Master-key immutability (`name`/`can_manage_keys` refused on `PUT /api/keys/{id}` against the Master, `bound_ips` still permitted), key deletion with endpoint reassignment (`409` structured inventory without `reassign_to`; atomic reassignment-plus-delete with it; a nonexistent `reassign_to` target rejected with nothing changed), and concurrency (two identical signed requests racing the replay guard; two concurrent deletes of the same resource racing `rows_affected`). |
| `tests/common/mod.rs` | Shared fixtures: `setup_test_db` (migrated in-memory SQLite), `test_state` (plaintext-cipher `AppState`), `insert_key` (seeds an `api_keys` row and returns its plaintext credentials), and the `CANONICAL_V1` request-signing helpers (`signed_request`/`signed_request_at`/`with_connect_info`) that every integration test builds its requests through. |
| `tests/source_hygiene.rs` | Static source-hygiene checks nothing else in the build enforces, per `AGENT.MD`. Raw SQL: `no_raw_sql_outside_the_documented_exceptions` (marker-API scan) and `no_dml_keyword_is_hand_written_outside_the_exceptions` (scans for hand-written DML *inside string literals*, not just marker APIs) over `RAW_SQL_ALLOWED` — a `(path, reason)` list, each entry checked by `no_raw_sql_handler_is_ever_exempted` (no `src/api/` path may ever be exempted) and `every_allowlisted_raw_sql_exception_still_exists_and_is_still_needed` (an allowlist entry naming a path that no longer exists or no longer contains raw SQL must be dropped), plus `the_raw_sql_scanner_detects_what_it_is_looking_for` proving the scanner can actually see a violation (ported and strengthened from `example/simply_ip_vault`'s version — see `AGENT_NOTES.MD`'s 2026-08-17 session 2 entry). `no_unwrap_or_expect_in_production_code`, file-scanning over `src/` cut off at each file's `#[cfg(test)] mod tests` boundary — `every_source_file_places_its_test_module_last` independently verifies that boundary-detection heuristic itself. Plus `app_js_has_no_syntax_errors` (an `oxc_parser`-based real ECMAScript parse of `static/app.js`), `every_dom_id_referenced_in_app_js_exists_in_index_html` (cross-checks every `el('...')` lookup against `static/index.html`'s `id=` attributes), and `no_hardcoded_absolute_path_bypasses_the_subpath_request_base` (2026-08-24: scans `static/app.js` for any `fetch(` call whose argument is a literal starting with `/`, which would bypass `REQUEST_BASE` and hardcode a root-relative URL — the exact class of bug that broke this dashboard behind a reverse-proxy subpath). Each check that scans for a defect ships its own self-test proving it actually fires against a deliberately broken fixture before being trusted against the real files. |

Unit tests live beside the code they test, in `#[cfg(test)] mod tests` blocks within the `src/`
files listed above (80 of them, at last count) rather than in a separate directory — see each
file's own `tests` module for its specific coverage.
